# 自动化骨架点修正改进建议（精简修订版）

本文档针对当前仓库的 2D/3D 姿态流水线，目标是减少逐帧拖点，而不是用规则完全替代人工。

## 1. 结论

当前项目适合建设“自动发现异常、保守生成修正建议、人工只复核异常片段”的半自动流程。推荐优先级如下：

1. 先降低主体跟踪错误，并生成异常片段报告。
2. 只自动修正低置信度、短时缺失和明显跳点的 2D 关节。
3. 重新执行 MotionAGFormer，再对 3D 做骨长和时序软约束。
4. 将人工编辑点作为锁定锚点，传播到相邻帧。
5. 最后再评估 HSMR/SKEL，暂不放进主流程。

运动学约束可以直接帮助修点；受力、力矩等动力学约束目前不适合直接加入。原因是当前 3D 结果没有公制尺度、相机标定、冰面方程和人体质量参数，无法可靠计算真实动力学量。

## 2. 当前能力与数据边界

现有流程已经支持：

```text
视频 -> MMPose/RTMPose 2D
     -> select_main_skater_h36m.py（主体选择、COCO-17 转 H36M-17）
     -> lift_2d_to_3d_motionagformer_ap3d.py（时序 3D 抬升）
     -> 2D/3D 编辑器
     -> corrected JSON 转 NPZ
     -> 重新抬升或生成查看器
```

实施自动修正时必须保留以下边界：

- `h36m_keypoints` 的形状为 `(T, 17, 3)`，第三维是检测置信度；`root`、`spine`、`thorax`、`head` 是由 COCO 点合成的，并非独立检测结果。
- 未选中人物的帧以零值保存，同时 `selected_indices == -1`。这些帧必须先作为缺失数据屏蔽，不能把坐标零当成真实关节点。
- 当前主体选择使用相邻帧 bbox、中心距离和置信度进行贪心匹配。若选错人物，后续平滑会把错误变得更连续，却不能修复身份错误。
- MotionAGFormer 输出是 root-relative、按图像宽度缩放的相对坐标，不是相机坐标或米制世界坐标。
- 2D 编辑器会把人工拖拽点的分数提高到 `1.0`。自动修正不应伪造检测置信度，应另存自动修正掩码和修正权重。
- 自动结果必须写入新文件，并记录源文件、参数和修正掩码，不能覆盖原始检测结果。

## 3. 推荐方案

### 3.1 主体跟踪与异常报告（最高优先级）

首先改进 `select_main_skater_h36m.py`：

- 从逐帧贪心选择改为整段轨迹选择，可使用动态规划，综合 bbox IoU、中心距离、姿态距离和检测分数。
- 设置合理的拒绝条件；没有可信候选人时保留缺失状态，不强行选择一个人。
- 输出每帧 bbox、轨迹得分、缺失状态和疑似 ID 切换标记，方便定位问题。

新增 `scripts/analyze_pose_anomalies.py`，只生成报告，不修改数据。报告以连续异常片段为单位，而不是产生大量单帧告警。建议检测：

- 人物缺失、跟踪得分骤降或疑似 ID 切换；
- 2D 低置信度、速度或加速度突变；
- 局部骨长比例突变、左右肢体疑似互换；
- 3D 骨长漂移、速度或加速度突变；
- 人工编辑点与模型输出差异较大的区域。

速度类指标应按真实 FPS 计算，并用 bbox、躯干长度等尺度归一化。阈值宜采用中位数和 MAD 等稳健统计量，避免用固定像素阈值适配所有视频。

### 3.2 保守的 2D 自动修正

新增 `scripts/refine_2d_pose_temporal.py`，仅处理以下情况：

- 低置信度关节的短时缺失；
- 相对前后帧明显孤立的跳点；
- 已有人工关键帧之间的过渡帧。

修正规则：

- 高置信度点和人工确认点保持不动；
- 短缺口使用线性或 PCHIP 插值，避免普通三次插值产生过冲；
- 平滑强度由置信度和局部运动速度控制，快速旋转、起跳和落冰阶段应减弱平滑；
- 2D 骨长只能作为局部软约束，不能在全视频中强制恒定；
- 合成关节优先由修正后的髋、肩和头部检测点重新计算，不宜与真实检测点独立优化；
- 不跨越 ID 切换、长时间缺失、镜头切换或人工锁定边界插值。

建议保留以下附加字段：

```text
h36m_keypoints_original
h36m_keypoints
auto_refined_mask
refinement_weight
refinement_method
```

原始置信度继续表示检测器可信程度，自动修正可信程度放在 `refinement_weight` 中，两者不要混用。

### 3.3 3D 约束修正

2D 修正后必须重新运行 MotionAGFormer，再执行 `scripts/refine_3d_pose_constraints.py`。第一版只建议包含：

```text
总损失 = 原始 3D 贴近项
       + 置信度加权的骨长一致性项
       + 自适应时序项
       + 人工锚点项
```

具体要求：

- 标准骨长从可靠帧稳健估计，排除缺失、低置信度和明显异常帧；
- 时序项按 FPS 和局部动作速度调整，避免抹平跳跃、旋转和落冰冲击；
- H36M 的 `root` 应保持为零。3D 编辑器中应锁定 root，或将其操作定义为整体平移，不能只移动 root 一个点；
- 人工编辑关节作为强锚点，自动优化只调整未锁定点及其邻近过渡帧；
- 关节角度先用于告警或软惩罚，不使用硬截断。H36M-17 点集无法完整表达肩、髋等关节的真实旋转自由度。

当前阶段不建议加入以下约束：

- 严格冰面接触和足底防滑：当前没有稳定的冰面、脚掌朝向和动作阶段信息；
- 力、力矩和质心动力学：当前 3D 不是公制世界坐标；
- 严格 3D 到 2D 重投影：当前没有标定相机。拟合弱透视相机后可将重投影误差用于异常排序，但不能视为准确性真值。

## 4. 编辑器改进

自动化功能应优先服务于复核，而不是直接批量覆盖：

- 在时间轴标记异常片段，并提供“上一个/下一个异常”；
- 同时显示原始点、自动建议点和当前编辑点；
- 支持按关节或按片段接受、拒绝自动建议；
- 人工确认点可锁定，并在 JSON 中保存锁定状态；
- 保存自动修改、人工接受和人工覆盖的操作记录。

这样用户只需检查高风险片段，同时所有自动修改都可追溯和撤销。

## 5. HSMR/SKEL 的合理定位

HSMR 可以提供比 H36M-17 更完整的人体结构和形状先验，但目前不能直接接入现有 NPZ：

- HSMR 公共视频 demo 可以逐帧预测 SKEL 人体，但没有显式的视频时序优化；
- SKELify 示例输入是裁剪图像坐标中的 44 个关键点（Body25 + 19 个额外点），当前项目只有 COCO-17/H36M-17；
- HSMR/SKEL 与 MotionAGFormer 的关节定义、裁剪变换、相机模型、尺度和坐标系均不同；
- 单帧分别估计 body shape 会造成身体比例随时间变化，应在同一人物序列中共享或稳健汇总 shape 参数。

因此 HSMR 第一阶段只适合作为旁路实验：

1. 对异常片段运行 HSMR，生成独立的解剖结构候选。
2. 完成 SKEL 到 H36M-17 的关节映射和相似变换对齐。
3. 比较骨长、关节位置和时序稳定性，用冲突程度辅助异常排序。
4. 在代表性片段上证明有效后，再考虑改造 SKELify 的关键点损失和时序约束。

不建议直接用 HSMR 替换 MotionAGFormer，也不建议在未完成相机与坐标对齐前，用 HSMR 投影点覆盖原 2D 检测。

## 6. 建议流水线与实施顺序

```text
2D 检测
  -> 全序列主体跟踪
  -> 异常片段报告
  -> 保守的 2D 自动修正
  -> MotionAGFormer 重新抬升
  -> 3D 骨长/时序软约束
  -> 编辑器复核异常片段
  -> corrected JSON/NPZ 和质量报告
```

建议分四步落地：

1. 改进主体跟踪，新增异常报告，并让编辑器支持异常导航。
2. 实现 2D 短缺口和孤立跳点修正。
3. 实现 3D 骨长、时序和人工锚点优化。
4. 小规模验证 HSMR 旁路，不急于封装总流水线。

等各模块的输入输出和阈值稳定后，再新增 `run_auto_pose_refinement_pipeline.py`，避免过早把尚未验证的步骤固化进主流程。

## 7. 验收标准

先选取一组包含滑行、旋转、跳跃、落冰和遮挡的代表性片段，人工标注少量 2D 真值和错误类型。每次改动都比较原始、自动修正、最终人工修正三份结果。

主要指标：

- 2D PCK/NME 是否优于原始结果；
- 异常报告的召回率，以及前 Top-K 片段中真实错误的比例；
- 自动建议接受率、人工复核片段数和总耗时；
- 高置信度原始点被错误移动的比例；
- 若有 3D 真值，使用 MPJPE/PA-MPJPE；没有 3D 真值时，采用盲测观看和人工修正量作为主要判断。

骨长方差、加速度和 jerk 只能作为辅助指标。过度平滑也会让这些数值下降，因此不能单独证明 3D 更准确；“低置信度点数量减少”也不应作为目标，因为算法不应通过修改置信度制造改进。

最终目标是让人工从逐帧检查，转为确认少量异常片段和关键帧，同时保证复杂花样滑冰动作不会被过强约束修坏。
